# 캠퍼스 길찾기

신입생이 건물 이름을 검색하면, 그 건물의 가장 가까운 입구까지 걷는 길을 카카오맵 위에 그려 주는 웹 앱이에요.
서버나 빌드 과정 없이 정적 파일만으로 동작하고, Vercel에 그대로 올리면 돼요.

## 화면

| 주소 | 파일 | 누가 쓰나 | 하는 일 |
| --- | --- | --- | --- |
| `/` | `index.html` | 신입생 (휴대폰) | 건물 검색, GPS 위치, 경로 안내, 도착 알림 |
| `/gps-test` | `gps-test.html` | 팀 (휴대폰, 현장) | 실제 위치와 GPS 위치의 차이 측정, 결과 JSON 저장 |
| `/editor` | `editor.html` | 팀 (PC) | 건물, 입구, 인도 그리기와 검증, `campus.geojson` 저장 |

## 파일 구조

```
index.html          신입생용 길찾기
gps-test.html       GPS 정확도 측정
editor.html         데이터 편집기
js/config.js        캠퍼스 이름, GPS 기준값 같은 설정 (키는 비워 둠)
js/config.local.js  카카오·Supabase 키 (git 제외, config.local.example.js를 복사해서 만듦)
js/core.js          경로망 만들기와 최단 경로 계산 (세 화면이 함께 씀)
js/chatbot.js       챗봇 엔진 (건물 인식, 질문 종류 판단, 단계별 길 안내 문장)
js/guide.js         걷는 동안 경로 따라가기와 음성 안내 시점 판단
js/kakao.js         카카오맵 SDK 불러오기
data/campus.geojson 캠퍼스 데이터 (편집기에서 저장한 파일로 덮어쓰기)
data/gps-tests.json GPS 측정 결과 (측정 페이지에서 내보낸 파일로 덮어쓰기)
data/route-tests.json 길찾기 현장 테스트 기록 (?test=1 모드에서 내보낸 파일로 덮어쓰기)
tests/run.js        자동 테스트 (node tests/run.js)
vercel.json         Vercel 설정 (주소 정리, 데이터 캐시 끄기)
```

## 처음 설정

1. 카카오 디벨로퍼스에서 앱을 만들고 카카오맵을 켜요.
2. **[앱] > [플랫폼 키] > [JavaScript 키]** 에서 키를 복사해 `js/config.local.js`의 `kakaoKey`에 넣어요. `js/config.local.example.js`를 복사해서 만들고, 이 파일은 git에 올라가지 않아요.
   JavaScript 키는 원래 브라우저에 공개되는 키라 저장소에 올라가도 괜찮아요. 대신 등록한 도메인에서만 동작해요.
3. `mapCenter`를 캠퍼스 위치 `[위도, 경도]`로 바꾸고 `campusName`도 채워요.
4. 같은 키 화면의 **[JavaScript SDK 도메인]** 에 아래 주소를 등록해요.
   - 로컬 테스트: `http://localhost:8000`
   - Vercel 배포 주소: `https://<프로젝트이름>.vercel.app`

`*.vercel.app` 같은 넓은 와일드카드는 등록하지 마세요. 다른 사람의 Vercel 사이트에서도 우리 키를 쓸 수 있게 돼요.

## 로컬에서 보기

```bash
python -m http.server 8000
# http://localhost:8000          길찾기
# http://localhost:8000/editor.html   편집기
```

로컬 서버에서는 `/editor` 대신 `/editor.html`처럼 확장자를 붙여야 해요. Vercel에서는 둘 다 돼요.

## Vercel 배포

GitHub 저장소를 Vercel에서 Import하면 돼요. 프레임워크는 Other, 빌드 명령과 출력 폴더는 비워 둬요.
`main` 브랜치에 푸시할 때마다 자동으로 다시 배포돼요.

## 데이터 고치는 흐름

1. 배포된 `/editor`에서 "배포된 데이터 불러오기"를 눌러요.
2. 고친 뒤 검증 탭에서 오류가 없는지 확인해요.
3. "JSON으로 저장"으로 받은 `campus.geojson`을 저장소의 `data/campus.geojson`에 덮어쓰고 푸시해요.
4. 배포가 끝나면 길찾기 화면에 바로 반영돼요.

편집기의 임시 저장은 각자 브라우저에만 남아요. 여러 명이 동시에 고치면 마지막에 올린 파일이 이기니, 구역을 나눠 작업하고 한 사람이 합쳐서 올리세요.

## GPS 정확도 측정 방법

1. 휴대폰으로 배포 주소의 `/gps-test`를 열어요. (위치 기능은 https에서만 동작해요)
2. 등록된 입구 앞에 서서 그 입구를 고르거나, 스카이뷰에서 서 있는 곳을 정확히 찍어요.
3. 1~2분 가만히 서서 측정하고 저장해요. 트인 곳, 건물 사이, 입구 바로 앞 등 여러 환경에서 반복해요.
4. "JSON으로 내보내기"로 받은 `gps-tests.json`을 `data/gps-tests.json`에 덮어써서 팀과 공유해요.
5. 실외 측정이 3곳 이상 모이면 화면이 `arriveRadius` 값을 추천해 줘요. `js/config.js`에 반영하세요.

## 챗봇

길찾기 화면 오른쪽 위 말풍선 버튼으로 열어요. 외부 AI API 없이 브라우저에서 동작해서 비용이 들지 않고, 등록된 데이터에 없는 내용은 지어내지 않아요.

- 건물 인식: 이름, 별칭, 건물 번호, 초성(ㅈㅇㄷㅅㄱ), 오타(자모 단위 편집 거리). 숫자가 다른 이름(제1공학관과 제3공학관)은 오타로 보지 않아요.
- 질문 종류: 길찾기, 운영시간, 층(강의실 번호에서 층 추정), 출입구, 휠체어·엘리베이터, 편의시설, 소개, 인사, 도움말
- 층별 안내: "과사무실 어디야?", "컴공 과사무실 몇 층?", "도서관 3층에 뭐 있어?", 이어서 "4층은?", "공대 305호 어디?"(강의실 범위로 층 찾기). "컴공", "전자과" 같은 줄임말도 알아들어요.
- 맥락: "거기 몇 시까지 해?", "2공은?"처럼 앞 대화를 이어받아요.
- 길찾기 답에는 "80m 직진 → 왼쪽으로 꺾어서 40m" 같은 단계별 안내가 붙어요.
- 답의 재료는 편집기의 건물 정보(층, 운영시간, 편의시설, 소개)와 출입구 정보예요. 여기를 채울수록 챗봇이 똑똑해져요.

`?ask=도서관 몇 시까지 해` 형태로 열면 그 질문으로 채팅이 바로 시작돼요.

## 음성 안내

길 안내를 시작하면 브라우저에 들어 있는 음성 합성(Web Speech API)으로 안내해요. 서버나 비용이 들지 않아요.

- 시작할 때 목적지, 거리, 예상 시간을 말해요.
- 경로와 안내 단계는 출발할 때 한 번만 만들고, 걷는 동안은 GPS를 그 경로 위에 투영해서 얼마나 왔는지만 계산해요. GPS가 길 옆에 찍혀도 가짜 꺾기가 생기지 않아요.
- 꺾기로 보는 곳: 갈림길에서 40° 이상, 또는 갈림길이 아니어도 100° 이상 급하게 꺾이는 곳. 휘어진 길은 안내하지 않아요.
- 꺾는 곳까지 경로를 따라 남은 거리가 `turnAnnounce`(기본 15m)에 말하는 2초 동안 걸을 거리를 더한 거리 안으로 들어오면 한 번만 말해요.
- 첫 꺾기가 가까우면 출발 안내에서 "직진하세요" 대신 그 꺾기를 함께 말해요.
- 15m 안에서 연달아 꺾으면 "왼쪽으로 꺾은 뒤, 곧 오른쪽으로"처럼 묶어서 말하고, 직전 안내 4초 안에는 겹쳐 말하지 않아요.
- 경로에서 `offRouteDistance`(기본 15m) 이상 벗어난 상태가 두 번 연속일 때만 경로를 다시 찾아요.
- 도착은 한 번만 판단하고, 그 뒤로는 안내를 멈춰요.
- 경로를 다시 찾거나 더 가까운 입구로 바뀌면 알려 주고, 도착하면 말해요.
- 안드로이드에서는 꺾을 때 진동도 줘요(오른쪽 한 번, 왼쪽 세 번). 아이폰 브라우저는 진동을 지원하지 않아요.
- **기본은 꺼져 있어요.** 실기기 검증이 끝날 때까지는 사용자가 오른쪽 스피커 버튼을 눌러 켜야 해요. 켜고 끈 선택은 기억되고, 진동도 음성을 켰을 때만 동작해요.
- 아이폰은 화면을 한 번 눌러야 소리가 나서, "길찾기"를 누를 때 첫 안내를 말해요.

## 외부 챗봇 연동

챗봇이 아래 형태의 링크를 보내면, 길찾기 화면이 그 건물을 바로 열고 GPS가 잡히는 대로 경로를 그려요.

```
https://<배포주소>/?to=중앙도서관
https://<배포주소>/?to=공대&start=37.12345,127.12345   (출발점 지정, 위도,경도)
```

`to`에는 건물 이름, 별칭, 건물 번호 중 아무거나 넣어도 돼요.

## 자동 테스트

```bash
node tests/run.js
```

외부 패키지 없이 돌아가고, GitHub에 푸시할 때마다 Actions에서 자동으로 실행돼요(저장소의 Actions 탭에서 결과 확인).

- **경로 엔진:** 교차점 분할, 끝점 붙이기, 가장 가까운 입구, 계단 회피, 공사 구간 제외, 끊긴 길 찾기, 운영시간
- **데이터:** 형식, id 중복, 좌표 범위, 건물마다 입구, 층별 안내 형식, 하나로 이어진 인도, 여러 출발점에서 모든 건물까지 경로
- **챗봇:** 실제로 할 법한 질문 35개와 모든 건물 이름·별칭 인식
- **길 안내:** 걷는 중 다시 계산해도 꺾는 방향이 바뀌지 않는지, 출발과 도착이 제대로 붙는지
- **음성 안내:** 현장 기록(`data/route-tests.json`)을 앱과 같은 로직으로 그대로 재생해서, 도착 안내 한 번, 출발 안내 모순 없음, 꺾기 안내 거리, 안내 겹침, 안내 도배를 검사

데이터를 고친 뒤 테스트가 빨간불이면, 메시지에 어느 건물의 무엇이 문제인지 나와요.

## 현장 테스트 기록

길찾기 화면을 `?test=1`을 붙여 한 번 열면 테스트 모드가 켜져요(예: `https://배포주소/?test=1`). 이후 길찾기를 할 때마다 자동으로 기록돼요.

- 기록 내용: 목적지, 예상 거리·시간, 실제 걸린 시간, 걸은 거리, GPS 위치 기록, 음성 안내 문장과 시점, 꺾기 안내를 몇 m 앞에서 했는지, 경로 재계산, 자동 도착 판정 거리
- 도착하거나 "끝내기"를 누르면 결과 버튼(맞는 입구에 도착, 다른 곳에 도착, 길 안내가 이상했음, 중간에 그만둠)과 메모 칸이 나와요.
- 첫 화면에 성공률, 예상 대비 실제 시간, 꺾기 안내 평균 거리가 요약돼요.
- "JSON 내보내기"로 받은 `route-tests.json`을 `data/route-tests.json`에 덮어써서 팀과 공유해요.
- 끝나면 "모드 끄기"를 누르거나 `?test=0`으로 열면 꺼져요. 일반 사용자에게는 보이지 않아요.

## 데이터 형식 (`data/campus.geojson`)

GeoJSON FeatureCollection이고, 모든 항목은 `properties.kind`로 구분해요. 좌표는 `[경도, 위도]` 순서예요.

| kind | 도형 | 주요 속성 |
| --- | --- | --- |
| building | Polygon | `id`, `name`, `aliases`, `code`, 챗봇용 `floors`, `hours`, `facilities`(배열), `desc`, `memo`, `floor_info`(`[{ "floor": 3, "items": ["컴퓨터공학과 과사무실", "강의실 301~310"] }]`) |
| entrance | Point | `id`, `building_id`, `type`(main, side, stairs, elevator, parking), `floor`, `open_hours`("08:00-22:00"), `accessible`, `note` |
| path | LineString | `id`, `is_stairs`, `wheelchair`, `indoor`, `lit`, `active` |

## 실내 AR 길안내 (안드로이드 앱)

실외는 지도(카카오맵) 경로로 안내하고, 입구에 도착해 실내로 들어온 걸로 판정되면(또는 "건물에 들어왔어요" 버튼) AR 화면이 열려요.
ARCore 클라우드 앵커로 지금 위치를 잡고, 목적지(호실) 앞까지 걸었던 경로 위에 3D 화살표를 띄워요. 닫으면 2D 실내 안내로 돌아와요.

- 웹: `index.html`의 `startAR` (Capacitor 앱일 때만 동작, 브라우저에서는 그대로 2D 안내)
- 네이티브: `android/app/src/main/java/com/naeodiga/app/` — `IndoorArPlugin`(웹 연결), `ArNavActivity`(AR 화면), `Guidance`(화살표 위치·회전 안내), `Georef`(위경도 ↔ 지도 좌표), `NavMap`(경로 탐색·앵커 정렬), `ChevronMesh`/`ArRenderer`(그리기)
- 데이터: `android/app/src/main/assets/nav.json`(앵커 ID 포함 — 공개 금지, git 제외), `ar_meta.json`(지원 건물 코드 + 위경도 정합값)
- 인증: `android/cloud.properties`의 `apiKey=...`(git 제외). 앵커 TTL은 1일이라 만료되면 다시 촬영해야 해요
- 검사(JVM, 폰 없이): `cd android && ./gradlew :app:checkAr`
- 빌드: `npm run android` 후 `cd android && ./gradlew assembleDebug` (JDK 17, Android SDK 필요)
